# 新设备继续任务：拉取后还缺什么

> 目标：在另一台机器上继续 PiggyFarm / LevelForge。先拉仓库，再按本文补齐**没有进 Git**的运行时内容。

## 1. 仓库里已经有的

- 平台/内核/契约/前端源码；
- `adapters/piggyfarm/`：PiggyFarm 适配层源码 + 35 个测试 + 内嵌真实关卡模板；
- `docs/`：路径 B 操作手册、工具通用优化方案、本文件；
- `harness-templates/`、`skills/`、`PROGRESS.md`。

## 2. 没有进 Git（必须在新设备重建/配置）

| 内容 | 原因 | 新设备怎么做 |
|---|---|---|
| `data/`（SQLite、插件 DLL、磁带、基准、确认记录） | `.gitignore`，含本地运行时与 API Key | 启动平台会新建；需重新导入项目/关卡、重跑门禁 |
| `web/dist/` | `.gitignore`，构建产物 | `run.cmd` 首次会自动 `npm install && npm run build`；也可手动 `cd web && npm install && npm run build` |
| `node_modules/` | `.gitignore` | `cd web && npm install` |
| `bin/`、`obj/` | `.gitignore` | `dotnet build` |
| 适配层 DLL | 只提交源码 | `cd adapters/piggyfarm && dotnet build ... -c Release`，把 DLL 放到 `src/LevelForge.Platform/data/plugins/piggyfarm/` |
| 游戏工程 `PiggyFarm` | 不在工具仓库 | 单独拷贝/克隆到新设备；设置 `PIGGYFARM_PROJECT_ROOT` 供语料测试 |
| LLM 配置 | 存在本地 SQLite，含密钥 | 启动后到“设置”重新填 baseUrl/apiKey/model |
| 已导入的 33 关、门1/门3 记录、baselines | 存在本地 DB | 重新导入关卡、重新跑门1/门3；旧证据本来也不能跨机器复用 |

## 3. 新设备最短启动路径

```powershell
git clone https://github.com/Xiyuun/AI-Level-Solver.git
cd AI-Level-Solver

# 后端 + 前端
.\run.cmd        # 首次会 npm install/build，然后 http://localhost:5000

# 适配层（另开一个终端）
cd adapters\piggyfarm
$env:PIGGYFARM_PROJECT_ROOT="D:\path\to\piggyfarm"   # 可选：语料测试用
dotnet test LevelForge.Adapters.PiggyFarm.Tests\LevelForge.Adapters.PiggyFarm.Tests.csproj -c Release
dotnet build LevelForge.Adapters.PiggyFarm\LevelForge.Adapters.PiggyFarm.csproj -c Release
```

把 `adapters\piggyfarm\LevelForge.Adapters.PiggyFarm\bin\Release\net10.0\LevelForge.Adapters.PiggyFarm.dll`
复制到 `src\LevelForge.Platform\data\plugins\piggyfarm\`，重启平台，在向导③检测/门1。

## 4. 环境要求

- .NET SDK **10.x**（`dotnet --list-sdks` 有 10）；
- Node.js（`run.cmd` 用 `%USERPROFILE%\nodejs` 或 PATH 里的 node）；
- 平台同一时间只跑一个实例（SQLite 写锁 + 插件 DLL 文件锁）。
