> **2026-11-17 起新增一键部署：`setup.cmd`（Windows）/ `setup.sh`（bash）——见 §2，大多数情况只需跑它。**

- `docs/`：路径 B 操作手册、工具通用优化方案、本文件；`harness-templates/`、`skills/`、`PROGRESS.md`（§10 为逐日进度与决策记录）。

## 2. 一键部署（推荐路径）

```bat
git clone https://github.com/Xiyuun/AI-Level-Solver.git
cd AI-Level-Solver
setup.cmd          & rem Windows（bash 环境用 setup.sh）
run.cmd            & rem 启动 http://localhost:5000
```

`setup` = 构建解决方案 + 前端 + 全量测试 → 构建并部署 mahjong/piggyfarm 插件 DLL 到 `data/plugins/` → 打印启动清单。完成后所有核心功能（求解/质检/出题/预览回放/门1/批量）即可用。

前置要求：.NET SDK 10.x、Node.js（见 §4）。

## 3. 没有进 Git（必须在新设备重建/配置）

| 内容 | 原因 | 新设备怎么做 |
|---|---|---|
| `data/`（SQLite、插件 DLL、磁带、基准、确认记录、明文 API Key） | `.gitignore`，本地运行时状态 | `setup` 重建插件 DLL；启动自动建库并种子内置关卡/玩法行；**设置页重填 LLM 地址/Key/模型**（出题功能需要） |
| `web/dist/`、`node_modules/` | 构建产物 | `setup` / `run.cmd` 自动构建安装 |
| `bin/`、`obj/` | 构建产物 | `dotnet build` |
| 游戏工程本体（PiggyFarm、mahjong_260417） | 不在工具仓库 | 单独拷贝/克隆到新设备；向导①/设置里把关卡根目录重新指向工程内关卡目录后重新导入语料 |
| 已导入语料、门1/门3 记录、baselines、已采纳关卡 | 存在本地 DB/文件 | 重新导入、重跑门禁；旧证据本就不能跨机器复用 |
| 门2 harness 与游戏可执行体 | 依赖游戏工程 | 按规则矩阵与 replay-spec 重新配置（mahjong 需按 initFromPreloaded 口径加载全预设关） |

环境要求：.NET SDK **10.x**、Node.js；平台同一时间只跑一个实例（SQLite 写锁 + 插件 DLL 文件锁；更新插件 DLL 必须先停平台）。

## 4. 手动路径（等价于 setup 的分步说明）

```powershell
git clone https://github.com/Xiyuun/AI-Level-Solver.git
cd AI-Level-Solver
build.cmd                                   # 后端构建 + 全量测试 + 前端构建

deploy-plugins.cmd                          # 构建并部署 mahjong + piggyfarm 插件 DLL
run.cmd                                     # 启动平台
```

- mahjong 玩法行/视觉映射/内置语料 1 号关随插件装载自动恢复（UpsertGame）；
- piggyfarm 语料测试可选：`$env:PIGGYFARM_PROJECT_ROOT` 指向游戏工程后 `dotnet test adapters/piggyfarm/...Tests.csproj`；
- 各玩法功能对照：mahjong 见 PROGRESS §10.19/10.20 与 `adapters/mahjong/onboarding-output/`；piggyfarm 见 §10.16/10.17。
