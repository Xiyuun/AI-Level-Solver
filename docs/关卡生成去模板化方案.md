# 关卡生成去模板化方案（PiggyFarm）

> 状态：**已实施（2026-11-18）**。模板库 `PiggyFarmTemplates.cs` 已删除，改为 `PiggyFarmSynthesizer` 逆向构造。
> 实施记录与实测 A/B 见 `PROGRESS.md` §10.36；本文保留设计推导，文末 §15 记录"实施与设计的差异"。
> 关联代码：`adapters/piggyfarm/LevelForge.Adapters.PiggyFarm/`

---

## 0. 一页结论

1. **你的判断是对的，而且问题比"用了模板"更具体**：几何来自 **13 张固定关卡图**（2 档 7 张、3 档 6 张；
   其中 12 张是项目原生关卡、1 张是密集剥离样本），每次生成只做「4 选 1 对称 + 随机删 0~8 只猪 + 特殊猪布点」，
   **骨架永远不出这 13 张图**。
2. **两处放大器**让重复感更强：① 24 次尝试全失败时**固定回退 `templates[0]`**（2 档=374、3 档=19），
   历史记录里曾出现「11 次产出全是 374」；② 这些模板互相之间的占格相似度已经高达 **0.61~0.94**——
   玩家看到的"相同特征"（走廊走向、空洞位置）本来就在池内反复出现。
3. **方案：删掉模板库，改成"逆向构造生成器"**——从终局倒推一条合法解，边构造边记录见证解（witness）。
   构造出来的关卡**天生可解**（可回放验证），再叠加「风格采样 → 质量闸 → 档位闸 → 多样性闸」四层控制。
4. **质量不降级**用真实关卡的结构包络做验收（已实测 12 张原生关卡：密度 0.67~0.85、初始可离场 8~19%、
   受阻 69~88%、空洞连通块 4~23），新生成关卡必须落在同一包络内，并与旧产出做 100 关 A/B。
5. 代价：单关构造多 20~80ms，求解验证沿用现状；生成空间从「13 骨架 × 4 对称」变成指数级，
   同种子仍可复现。**1 档的 6 猪模块（flat 模板）一并删除**。

## 1. 问题确认（有证据，不是猜测）

### 1.1 现在的生成链路

```
LLM 只输出 {"band":2}
        │
        ▼
PiggyFarmComposer.Compose                       PiggyFarmComposer.cs:73-194
   ├─ templates = Band2 / Band3                 PiggyFarmTemplates.cs:5722-5723（7 个 / 6 个真实关卡 JSON）
   ├─ templateIndex = random.Next(len)          :100
   ├─ symmetry = random.Next(4)                 :102   （水平/垂直/180° 翻转，TransformTemplate :614）
   ├─ DeleteRandomPigs(0~8 只)                  :107 → :653
   ├─ PlaceRequirements（特殊猪改写普通猪）      :110 → :202
   ├─ 校验 / 质量门 / 求解 / 判档                :122-169
   └─ 24 次全失败 → 固定 templates[0] 兜底       :179-193
```

### 1.2 实测：多样性上限有多低

对 13 张模板做结构比对（占格集合 Jaccard、逐格朝向一致率、空洞连通块）：

| 对比 | 占格 Jaccard | 逐格朝向一致率 | 说明 |
|---|---|---|---|
| 2 档池内任意两张模板 | 0.61 ~ **0.94** | 0.18 ~ 0.38 | 池子内部就已经长得很像 |
| 同模板 + 同对称，两次生成 | 0.90+ | **1.00** | 每格朝向/类型完全一致，只差删掉几只 |
| 不同模板/不同对称 | — | **0.25** | 0.25 就是"四选一"的随机水平 |

> 关键数字：**同模板+同对称时，逐格朝向一致率是 100%**、空洞 Jaccard 0.73。
> 对称变换不产生新特征（只是镜像），删 0~8 只猪对 77~112 只的关卡只改动 7~10% 的占格。

12×19=228 格，真实关卡占格 153~195 格（密度 0.67~0.85；密集样本 Dense112 是 224 格 / 0.98）。
**棋盘几乎被填满，所以"占格 Jaccard"天然偏高**，
玩家真正感知的是**空洞（走廊）的形状和朝向的排布**——这两样恰恰是模板决定的。

### 1.3 为什么会出现"连续两次几乎一样"

- 骨架池只有 7 / 6 张，撞上同一张的概率 = 1/7 × 1/4 ≈ 3.6%（2 档，且还不算对称）；
- 实际分布更集中：每次尝试按"能过判档+能求解"筛，**374 的成功率最高**，于是大多数产出都是 374（`PROGRESS.md` §10.32 实测 11/11）；
- 24 次全败时的兜底写死 `templates[0]`，批量 4 并发下很容易连续命中同一个骨架。

### 1.4 真实关卡的结构包络（质量基线，已实测）

| 指标 | 12 张原生真实关卡实测 | 说明 |
|---|---|---|
| 猪数 | 74 ~ 110（中位 91） | 2 档 74~99，3 档 79~110 |
| 占格密度 | 0.67 ~ 0.85（中位 0.81） | 几乎铺满 |
| 初始可直接离场 | 8% ~ 19%（中位 13%） | 大部分猪一开始是死的 |
| 初始受阻 | 69% ~ 88%（中位 79%） | 强依赖关系 |
| 朝向种类 | 4 | 密集样本 Dense112 只有 3 种 |
| 空洞格数 | 34 ~ 75（中位 43） | |
| 空洞连通块 | 4 ~ 23（中位 10） | **走廊是被切碎的多块，不是一大片空地** |
| 最大空洞 | 6 ~ 53（中位 17） | |
| 解长 / 猪数 | 1.2 ~ 1.7 | 89 猪 147 步（Level19）说明需要大量滑行 |

> 附：Dense112（112 猪 / 密度 0.98 / 初始可离场 38% / 空洞仅 1 块）是"剥离 + 密集填充"的极端样本，

这张表就是后面 §11 的验收线：**新生成关卡的这些指标必须落在同一区间**。

## 3. 总体方案

### 3.1 一句话

**用"先解后出题"取代"先找模板再改"**：随机生成一条合法解的过程，反过来就是生成关卡的过程；
解记录为见证，用来保证可解性、控制难度、并通过求解器复判。

### 3.2 四层结构

```
┌──────────────────────────────────────────────────────────────┐
│ L1 骨架构造  Synthesizer：逆向构造（witness-first）           │
│    输入：档位、风格向量、种子                                 │
│    输出：pig 布局（cells/facing/footprint）+ 见证解序列       │
├──────────────────────────────────────────────────────────────┤
│ L2 风格采样  StyleSampler：从真实关卡统计出的风格分布采样     │
│    密度曲线 / 空洞块数 / 朝向偏置 / 脚印配比 / 边界贴合度     │
├──────────────────────────────────────────────────────────────┤
│ L3 语义层  Specializer：特殊猪定型 + 需求契约（N 只 X 猪）    │
├──────────────────────────────────────────────────────────────┤
│ L4 闸门  Quality → Solve → Band → Diversity                  │
│    质量门（现有 3 条 + 新增 2 条）/ 求解判档 / 指纹去重       │
└──────────────────────────────────────────────────────────────┘
```

### 3.3 为什么不选另外三条路

| 备选 | 否决理由 |
|---|---|
| **A. 扩充模板池**（把 96 张可导入的真实关卡都塞进去 + 强化变异） | 违反"不要模板"的根本诉求；96 张仍是有限骨架，且池内相似度同样高 |
| **B. 随机撒猪 + 求解器筛选** | 12×19 上随机 90 只猪，可解概率接近 0，命中率会低到不可用（每关要试几千次）；且无法控制难度 |
| **C. 让 LLM 直接出几何 JSON** | `PROGRESS.md` 已记录：小模型出原生几何的失败率极高（88% 的候选死在格式/计数），token 成本高，与现有"结构化出题"方向相反 |
| **D. 本方案：逆向构造** | 可解性由构造保证（不是筛出来的），难度可参数化，空间指数级；代价是要写一套构造器 |

## 4. 核心算法：逆向构造（Witness-First Synthesis）

### 4.1 规则要点（来自适配层，必须严格一致）

- 点一只猪 → 沿朝向滑行，前方被**其它猪的占格**挡住就停在前一格，任一格越界则整只离场；
- 脚印：Normal/Boom/Zombie/Spring/Scissors/Balloon = 1×2（长边沿朝向）、Long/BalloonLong = 1×3、RichPig = 2×3、Duck = 1×1；
- 猪可以**被点多次**（每次滑到新的阻挡位），所以解 = 点击序列，长度 ≥ 猪数；
- 小黄鸭不可点、系绳气球不可点；弹簧滑行被挡会**弹回原位**（不位移）。

### 4.2 两个逆向操作（反向重建一条解）

设正向解为 `S0 --m1--> S1 --m2--> ... --mk--> Sk = 空`。从 `Sk` 出发倒着建 `S_{k-1} ... S0`：

| 逆向操作 | 对应正向动作 | 做法 |
|---|---|---|
| **Insert（加猪）** | 该猪点击后**离场** | 在空格上放一只新猪，要求它的**朝向直线上、到边界为止没有任何已放置的猪** → 它点一下就离场 |
| **PullBack（回拉）** | 该猪点击后**滑行但没离场** | 取一只已放置的猪 q（当前在 C），把它沿**反朝向**挪 k 格到 C'（要求途经格全空）→ 正向从 C' 点一下，会滑回 C 并被同一个阻挡挡住 |

**为什么这样构造一定可解**：每一步逆向操作都精确地定义了"正向走这一步会得到什么状态"，
所以把操作序列**倒过来**就是一条合法的点击序列，终点一定是空盘。构造器自己回放一遍即可自证（§10 M1 测试）。

### 4.3 不变量（构造器内部断言）

1. 任意时刻：已放置的猪两两不重叠、都在界内、脚印与（类型, 朝向）匹配；
2. Insert 的视线检查只看**已放置的猪**（它们都比新猪后离场，真正挡路的只能是它们）；
3. PullBack 的途经格在**当时状态**下为空；
4. 见证序列重放：每一步都是合法动作，最后 `Pigs.Count == 0`。

### 4.4 伪代码

```
Synthesize(band, style, seed):
  rng = Random(seed)
  for attempt in 1..K:
     plan = PlanFor(band, style)         // 目标猪数、滑步比例、脚印配比、空洞块数
     state = empty; witness = []
     while state.pigCount < plan.Pigs:
         if witness.slides < plan.Slides and rng.Chance(0.35) and PullBackPossible(state):
             q, k = PickPullBack(state, rng)      // 优先造"交叉互锁"
             ApplyPullBack(state, q, k); witness.push(Slide(q))
         else:
             spot = PickInsertSpot(state, rng, style)   // 视线畅通的空位 + 风格偏置
             if spot is null: break                    // 放不下了：回退这次尝试
             PlacePig(state, spot); witness.push(Exit(pig))
     if state.pigCount < plan.Pigs: continue
     if VerifyWitness(state, witness) fails: continue  // 自证
     return Level(state, witness)
```

- **K（尝试次数）**：构造很便宜，给到 100~200 次；只有"过了格式/质量门"的候选才进求解（烧预算）。
- **风格偏置**在 `PickInsertSpot` 里生效：比如 `density=高` 时优先贴着已有猪放；`pockets=多` 时故意留出孤立空格。

### 4.5 能填多满（可行性分析）

- Insert 的约束只是"直线上没有已放置的猪"。空盘时任意位置都合法；越到后面约束越紧，
  **靠近边界的、朝外的位置始终合法**（紧贴边界朝外 = 一步即离场）。
- 因此稠密关（密度 0.9+）的构造顺序应当是：**先放内部的、后放边缘的**——正好对应正向解里
  "内部的猪最后离场"。
- 造不上去时允许降密度（风格向量里密度是区间），3 档不要求必须 0.98。

### 4.6 交叉互锁：真实关卡的"灵魂"，也是本方案的重点

真实关卡里 **19~74 只猪处在互相阻挡的环里**（实测 13 张模板中 12 张有环，只有纯剥离的 Dense112 无环），所以玩家必须找到"先横挪一只、
给竖着的那只让路"的顺序。这正是 `PullBack` 造出来的东西：

```
行5   A  A  .  .  .  B  .        A 朝右，B 竖着挡在 A 的通道上（B 朝下、被 C 顶着）
行8   .  .  .  .  .  C  .        A 想走 → B 必须先向下滑到行 7（离开行 5）→ A 才能离场
```

- 构造时**故意**把新猪放进已有猪的射线里（新猪先离场，合法），就形成了"初始被挡"；
- `PullBack` 让某只猪在解里"先滑一段、再离场"，就形成了"必须先横挪"的强制顺序；
- 这两者叠加，生成的关卡在结构上就等价于真实关卡，而不是"一堆互不相干的直道"。

### 4.7 档位控制

平台难度分数 = `解长 + 0.2 × 平均分支`，阈值 `[20, 100]` → 1 档 `<20`、2 档 `20~100`、3 档 `≥100`。

| 档 | 目标猪数 | 目标滑步（解长-猪数） | 说明 |
|---|---|---|---|
| 1 | 6 ~ 18 | 0 ~ 2 | 小关，构造器直接出，不再平铺 6 猪模块 |
| 2 | 55 ~ 95 | 5 ~ 25 | 参照 374（77 猪 / 92 步） |
| 3 | 95 ~ 112 | 20 ~ 55 | 参照 Level19（89 猪 / 147 步） |

构造器先按目标出，**最后以平台求解结果为准**（求解后判档不符就调参数重来，与现状一致）。

## 5. 风格采样：让它像"人设计的"，不像"撒豆子"

纯随机构造容易产生"密度均匀、空洞散乱"的机器感。做法是**从真实关卡里统计一个风格向量**，逐关采样：

| 维度 | 取值方式 | 真实关卡参考 |
|---|---|---|
| 占格密度 | 0.67~0.85 分档采样 | 中位 0.81 |
| 空洞连通块数 | 4~23 | 中位 10 |
| 最大空洞尺寸 | 6~53 | 大空洞 = 一块开阔地 |
| 朝向直方图 | 4 种朝向的偏置（可失衡） | 4 种都有 |
| 脚印配比 | Normal 为主 + 少量 Long/RichPig | 真实关里 Long/RichPig 占比低 |
| 边界贴合 | 猪是否喜欢贴边 | |
| 对称性 | 0 / 水平 / 垂直（可选，非必须） | 真实关不总是对称 |

- 统计源：12 张内嵌真实关卡 + 用户项目里的 96 张可导入关卡（有语料时优先用语料）。
- 每个种子采一个风格向量，**同一批次的风格也互不相同**（这本身就是多样性的来源之一）。

## 6. 质量闸与多样性闸

### 6.1 质量门（现有 3 条保留，新增 2 条）

现有 `PiggyFarmQuality`（`PiggyFarmQuality.cs:8-39`）：朝向 ≥3 种、初始可走 ≤50%、受阻 ≥20%。

新增（只作用于生成候选，不拦导入的真实关卡）：

- **初始可离场比例 ≤ 25%**（原生真实关卡上限 19%，纯剥离样本才 38%）——防止"全是出口"的送分关；
- **解中非离场步 ≥ max(3, 猪数×5%)** ——保证至少存在"必须先挪位置"的结构（3 档要求更高）。

### 6.2 多样性闸

- **结构指纹**：12×19 → 3×5 密度 + 朝向直方图 + 空洞块数 + 脚印配比，量化成 20 维向量；
- **批次内去重**：同一批（或最近 N 次）里出现指纹距离 < 阈值的，重造（平台侧用一个轻量"最近指纹"表，
  通过 `ComposeContext` 传入，见 §9；不改变旧 composer 行为——加默认值即可）；
- **生成空间估算**：插入顺序 × 位置 × 朝向 × 回拉选择，量级 10^20+，撞车概率可忽略；
  去重闸主要是防"退化到某种固定模式"（比如某个种子的构造总是从小角落开始）。

## 7. 特殊猪需求（"至少 30 只小黄鸭"这类）

现状：模板上把普通猪改写类型。新方案分两层：

| 层 | 覆盖类型 | 做法 |
|---|---|---|
| **构造期定型**（推荐） | Normal / Long / RichPig / Zombie / Boom / Spring | 放猪时就决定类型，脚印约束相同；Boom/Spring 的语义差异（爆炸计数、弹回）在见证里按适配层规则处理，最后仍由求解器复判 |
| **后置布点**（兜底） | Duck / Scissors / Balloon / BalloonLong | 沿用现有 `PlaceRequirements`（纯类型改写 + 气球墙），失败就换一次构造；求解器仍是否决权 |

需求契约不变：**要求的类型必须出现、未要求的特殊猪不得出现**（现有"类型纯度"测试继续有效）。

## 11. 怎么证明"质量没降"（A/B 矩阵）

同一套指标，三个来源各 100 关（2 档/3 档各 50）：

| 组 | 来源 |
|---|---|
| R（真实） | 12 张原生真实关卡（另有 96 张语料时一并纳入） |
| O（旧） | 当前模板实现，固定种子 1..100 |
| N（新） | 新生成器，同种子 1..100 |

指标：猪数 / 密度 / 初始可离场比 / 受阻比 / 朝向种类 / 空洞块数 / 最大空洞 / 解长÷猪数 / 生成耗时 / 命中率 / 可解率。

通过线：

1. N 的全部结构指标落在 R 的 min~max 包络内；
2. N 的可解率 = 100%，档位命中率 ≥ O；
3. N 的「空洞 Jaccard」两两均值 ≤ 0.30（O 当前为 0.73 同一骨架 / 0.38 跨模板）；
4. N 的 p95 生成耗时 ≤ O × 1.5；
5. 人工抽检 10 关（工作台预览 + 解回放）无"明显机器感"。

## 15. 实施与设计的差异（2026-11-18 实施后补记）

设计稿（§4）只有 Insert / PullBack 两个逆向操作；实施时发现**纯随机布点会在 60~70 只时无处可放**
（每只新猪的正前方都必须为空，棋盘一密就没有合法位置），密度只能到 0.64。实际落地补了四件事：

1. **结构化铺排**（新增）：先按行铺"横链"（同一行同朝向，后放的猪挡住前面），再按列铺"纵链"
   （跨行依赖的来源），最后才用随机互锁布点补空隙 → 密度 0.64 → 0.80~0.92。
2. **封口脊**（新增，互锁深度的关键）：两侧边列铺成竖链，把每行横链的出口挡住（按 ~0.65 概率
   留部分行不封口当"呼吸口"）。初始可走比例 **29~33% → 6~16%**、受阻 **54~59% → 72~86%**，
   由此落进原生真实关卡的包络（8~19% / 69~88%）。脊上的猪天然是"贴边朝外"的安全落点，
   因此封口脊模式不再需要尾巴槽位。
3. **边界尾巴槽位**（设计稿已有）：非封口脊路径下，逆向最后插入的猪必须"贴边朝外"才合法；
   开局预留槽位、内层避开、最后落位。
4. **朝向兜底 + 需求预留块**：小关补一只缺朝向的猪（质量门要求 ≥3 种）；有土豪猪/大长猪需求时
   提前预留 2×3 / 1×3 空块（棋盘填满后未必还找得到）。

**难度来源**：设计稿原打算用"强制滑步（矩形环）"顶 3 档解长；实施改为"猪数 ≥100"（解长 ≥ 猪数 ≥ 100），
三档各 20 种子全部命中、单关 6~78ms，无需矩形环也能达标。
