## 3.1 七个必选成员（每个成员一段语义合同）

```text
LoadLevel(levelData) -> TState
  解析项目原生关卡数据（平台已读文件，适配层不做任何 IO）
  非法数据必须抛异常，禁止静默修复
GetLegalMoves(state) -> List<TMove>
  枚举当前局面全部合法操作
  同一状态多次调用结果必须一致（顺序稳定）；空列表 = 无合法操作
ApplyMove(state, move) -> TState        // 纯函数
  返回新状态；严禁修改入参；不读写任何外部状态
  move 必须来自本状态的 GetLegalMoves，非法操作抛异常
IsGoal(state) -> bool
  胜利判定；与游戏本体判定条件逐字一致
StateKey(state) -> string               // 规范化键
  逻辑相等 ⇔ 键相等；必须覆盖状态维度枚举的全部维度
  维度清单由资格报告草拟、开发者规则矩阵确认，实现须附"维度覆盖对照表"
DescribeMove(state, move) -> string
  人类可读描述（日志/磁带展示用，写清楚实体与方向）；不作为执行协议或无解因果证明
Snapshot(state) -> SceneSnapshot
  可渲染场景快照（格式见《渲染器与视觉映射规范》§2：格子层+实体层+globals）
  实体 id 全局稳定；纯函数；必须满足状态可视覆盖
  局部量与全局量都须映射可见；显示投影不代替完整规则状态
```

### 项目执行协议（与七成员配套的序列化/投影约定）

适配包提供结构化 TMove 的编码/解码、`moveSchemaVer`、语义状态投影及 `semanticSchemaVer`：

- 动作字段应能**无歧义定位目标及参数**；禁止从 DescribeMove 文本反向解析
- 语义投影覆盖规则矩阵中的位置、朝向、库存、剩余资源、阶段等**全部玩法字段**
- 适配侧从 TState 提取；harness 侧从游戏真实状态**独立提取**。允许共用字段定义/规范化器，**禁止共用适配器 ApplyMove 来产生游戏实报**

### 求解结果契约

`status / optimality / graphComplete / terminationReason / metricsScope` 以《求解内核》§5 为唯一枚举来源。早停 BFS 有最短路不代表全图已完成；**资源耗尽和取消不计作无解**。

## 3.2 铁律与强制执行

| 铁律 | 强制执行 | 覆盖限制（如实注明） |
|---|---|---|
| 零引擎依赖（不引用 UnityEngine/Cocos 运行时） | 依赖扫描（门1）拒绝加载 | 扫描的是引用名，混淆引用需人工核查 |
| 纯逻辑可复现（同一局面+同一操作序列，多次执行结果哈希一致） | 纯函数测试 + 完整语义深比较 | 比较限于已实现的语义字段 |
| 确定性（同输入、同版本、同配置双跑 trajectoryHash 一致） | 确定性双跑检查（门1） | artifactHash 仅文件完整性，不作行为摘要 |

违反任一条直接打回，不进验证门。规则矩阵和门2独立执行补充覆盖；测试通过不宣称任意未来输入正确。

## 3.3 可选能力接口

```text
IHeuristic      可采纳启发式（高估即破坏最优性保证——实现者必须自证 admissible）
ISeededRandom   仅随机复现草案；概率搜索需另定概率转移及结果契约，MVP 不启用
IMoveCategorizer 操作分类（难度特征的道具统计用；未实现时平台按"特征缺失"处理，不填 0）
```

声明方式：适配层实现接口并在 rule-matrix 注明；验证方式：各接口一组用例。

## 3.4 代码规范

- 目录：`adapter/`（实现）+ `adapter.tests/`（测试）；命名与平台仓库一致（C#：PascalCase、文件顶命名空间、`//` 中文注释同行末尾）
- 测试框架：与平台一致（xUnit）
- 禁止事项：无网络 / 无文件 IO / 无全局可变状态 / 无时间调用（`DateTime.Now` 类同禁——用传入种子或调用方时间）
