# qualification.md · 资格评估指令（阶段一）

> 产出物：`onboarding-output/qualification-report.md`
> 验收标准：四问各有结论 + 证据（文件:行号）；无证据的结论视为未完成。

## 1. 四问与判定信号（每问给出可搜索的代码模式）

### 问题 1：回合制？（操作是否离散回合驱动，无实时输入）
- 搜索模式：`Update()` 中的输入直驱、`FixedUpdate` 物理、帧率相关逻辑、`Input.GetKeyDown` 在结算路径中
- 通过：操作→结算→等待下一操作；结算与帧率无关
- 不满足的出路：**拒绝**（实时类不在版图）

### 问题 2：确定性？（规则代码中无随机源、无物理引擎参与结算）
- 搜索模式：`Random`/`UnityEngine.Random`/`System.Random`/`Guid`/时间戳参与结算、`Rigidbody`/`Physics2D` 在规则路径、浮点比较决定胜负
- 通过：同输入同输出可复现（允许表现层随机——粒子/音效/抖动，不进规则）
- 不满足的出路：随机类走期望搜索扩展路径（单列扩展需求）

### 问题 3：状态可枚举？（棋盘规模、实体数 → 状态空间上界估算）
- 估算方法：`棋盘格数^(实体种类数)` 或组合数上界；写出估算过程
- 通过：上界 < 10^8 量级（BFS 可行；内存按每状态约 512B 估）
- 不满足的出路：超界则需 IDA* 扩展（单列）或拒绝

### 问题 4：有持续产关需求？
- 判定方式：**人工确认**（问项目负责人：未来 3 个月产关计划）
- 通过：有明确计划
- 不满足的出路：**拒绝**（接入不回本——拒绝也是产出，别让人预付半天时间）

## 2. 证据义务

- 每问结论**必须附证据**：文件路径:行号（或问答记录）
- 拒绝给出无证据结论；代码无法自证的问题 → 转入问人流程（README 守则 1）

## 3. 附加产出（同报告内）

1. **规则代码定位图**：移动执行 / 碰撞阻挡 / 胜负判定 / 道具效果 各在哪些文件
2. **状态维度枚举**：位置、朝向、剩余步数、库存、阶段……（含估算过程；后续 StateKey 的维度覆盖对照以此为准）
3. **随机/物理证据清单**：表现层 vs 规则层的每处随机/物理逐条列出
4. **代码卫生度分级**：良好 / 一般 / 纠缠（判据：规则与 MonoBehaviour/场景引用的耦合程度；纠缠 → 接入预估上浮至 1~3 人日并明示）
5. **工作量预估**：按卫生度给出

## 4. 报告格式

```markdown

日期 / 评估者（agent 版本、skill 版本）/ 项目路径

## 规则代码定位图
## 状态维度枚举（估算过程）
## 随机/物理证据清单
## 代码卫生度与工作量预估
## 结论：通过 → 进入阶段二 / 拒绝+原因 / 需扩展+扩展项
```
